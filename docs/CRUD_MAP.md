## Rules to explain in the viva

- A student account stays when any booking, review or enrollment refers to it. A successful own-account deletion also ends the login session.
- Instructor management coordinates the teaching profile and its login account. Instructors referenced by assigned or requested lessons are retained. `AdminManagementController` is a shared file owned by 135 even where it exposes 133 or 136 operations.
- Availability and leave edits require the signed-in instructor to own the selected record; overlap and confirmed-lesson checks protect already promised teaching time.
- Cancellation changes a booking status. Rescheduling saves a new pending request and cancels the old one; the new request joins the FIFO tail. Permanent deletion is restricted to the student's own cancelled request.
- Vehicle deletion is refused while any lesson still refers to the vehicle.
- Package deletion is refused when an enrollment refers to it or a legacy booking stores its package ID directly. Deactivation retains the history.
- Enrollment UPDATE changes the learning goal, not the purchase amount or ownership. DELETE permits only owned, inactive, unpaid enrollments with no booking history. Paid receipts are retained.
- A review must concern the student's own completed lesson and is unique per lesson. Changed feedback returns to PENDING. Only approved feedback contributes to public instructor ratings.
- FileRepository supplies the common safe file operations; a repository override delegates to its parent and keeps those storage checks.
